# DocReadyApp

**Every Document. Perfectly Ready.**

A browser workspace for PDFs, images, signatures, scans, OCR, resumes and application documents. The app runs without a backend, account, API key or cloud file storage.

## Run locally

Use Node.js 22.18 or newer and npm. From the extracted `docreadyapp` directory, run the following commands.

```bash
npm ci --ignore-scripts
node scripts/assets.mjs
npm run models:prepare
npm run background:prepare
npm run dev
```

Open [the local app](http://127.0.0.1:5173/). The install step copies the pinned PDF.js auxiliary assets and Tesseract worker, engines and language models from the installed packages to `public/`.

Use the production preview to test offline behavior.

```bash
npm run build
npm run preview
```

Open [the local production preview](http://127.0.0.1:4173/). The ZIP includes the built `dist/` directory, so the build can also be served immediately by a static HTTP server from that directory. Serve it at the origin root over HTTPS or localhost. A direct `file://` launch cannot run the service worker and module workers.

## Deploy to Cloudflare Pages

1. For a git-connected Pages project, set the Node version to 22.18+ or 24, the build command to `npm run build`, and the build output directory to `dist`.
2. Set `VITE_PUBLIC_ORIGIN` to the final HTTPS origin, such as `https://documents.example.com`, and run the build. This generates static route metadata, canonical URLs and `sitemap.xml`.
3. For a direct upload, build locally with the desired origin and upload the **contents of `dist/`** using Cloudflare Pages Direct Upload. The included `_headers` sets the CSP and other response headers. Keep Pages’ default SPA fallback for unknown static routes. Other hosts should serve known assets first and fall back to `index.html` only for unknown application navigation routes.
4. After deploying, open a tool link directly, check the production response headers, and confirm OCR and offline reload in an HTTPS browser.

[Cloudflare Pages React setup](https://developers.cloudflare.com/pages/framework-guides/deploy-a-react-site/) · [Headers](https://developers.cloudflare.com/pages/configuration/headers/) · [Static routing](https://developers.cloudflare.com/pages/configuration/serving-pages/)

## OCR and AI Background Remover

OCR supports English, Hindi and the combined mode. Each PDF page or image is rendered and cleaned in a browser worker before Tesseract reads it. The editable result can be copied or exported as TXT or an editable Word document. Select up to 12 PDF pages per run.

The AI Background Remover uses IMG.LY's quantized IS-Net segmentation in a Web Worker with local CPU/WASM inference. It offers a comparison slider and transparent or solid-color PNGs at the original size. The model and runtime download from this site on first use and can be cached. Both tools process private inputs in the browser.

Before building from source, run `npm run background:prepare` to download the pinned model and verify its hashes. The background-removal worker and corresponding source and notices are available from the tool page under the IMG.LY AGPL terms.

## Unlock PDF

Open **PDF Studio → Unlock PDF**, select a PDF up to 40 MB, and enter its current open password. A local QPDF 12.4.2 WebAssembly worker decrypts and verifies a separate downloadable copy. The output keeps its pages and selectable text. Files that already open without a password, including files with permissions-only restrictions, are left alone. Digital signatures may become invalid in the new copy.

Only application assets are cached for offline use. Files and passwords stay in the active browser session. The pinned browser wrapper is `@soulehshaikh99/qpdf-wasm` 0.4.1 (ISC), with [QPDF](https://github.com/qpdf/qpdf/tree/v12.4.2), zlib and libjpeg-turbo notices in `public/licenses/pdf-unlock/`.

## File handling

### PDF suite and target-size compressors

The typed registry is `src/tools-config.ts`, connected to `src/catalog.ts`. Seven PDF navigation groups contain 32 tools; the separate Optimize / Image Tools group includes Image Compressor. `premium` is registry metadata: this checkout has no ad-gate or paid entitlement implementation to connect to.

PDF and image compressors offer Extreme, Recommended and Light presets, or a byte ceiling in KB/MB/GB (1024-based units). Exact mode tests encoder quality from 0.05 to 0.98 and lowers dimensions/render scale when needed. A target is a maximum size, not a promise of a padded exact byte count. Unreachable limits are reported. Inputs already under a target are returned unchanged. Batches offer individual outputs and a ZIP, with measured sizes and Vault actions.

Images use the raster worker and OffscreenCanvas when supported. PDF.js renders with its worker renderer, while a separate PDF worker assembles re-encoded pages. PDF compression rasterizes pages and removes selectable text, interactive fields, links and source signature verification; review the preview for QR/text readability. Browser image encoders may vary between devices. Current image retries stop after ten downscales or a 2,500-pixel minimum; PDF trials stop at 0.5 render scale. These safeguards can prevent very small targets being met.

Pinned vendor builds are copied to `public/libs` by `scripts/assets.mjs`; Vite ESM imports also produce same-origin `/assets` bundles. Production precaches static libraries and dependencies, never user files. This checkout uses a small local OOXML/CSV parser instead of the vulnerable npm SheetJS release; legacy XLS and full spreadsheet formatting are unavailable. PDF/A is excluded because metadata alone cannot establish PDF/A-1b compliance. See `PDF-SUITE-AUDIT.md` for remaining feature and verification limits.

The app reads uploaded file bytes in the browser and keeps them in memory while the tool is open. It creates downloads from local blobs. Only an explicit save writes a resume draft or application requirements to local storage. Preferences are saved by the settings form, and recent-tool history is opt-in. The service worker caches program assets and previously requested OCR models. OCR also uses IndexedDB for its language data. Settings can clear saved drafts, templates, preferences and OCR caches.

File size limits are 80 MB per input and 180 MB for supported batches. Image exports are limited to 16 megapixels and 10,000 pixels per side. PDF raster and per-page ZIP operations are capped at 40 selected pages, PDF OCR at 12 pages per run, and scans at 20 photos. Browser memory and available storage can impose lower limits.

For OCR, select English, Hindi, or both, then click Extract text to load the engine and requested language pack from the app’s origin. After loading and caching, the language can work offline. Recognition accuracy depends on the quality of the scan.

### Document scanner

The scanner detects page corners on-device. Adjust the four handles with a pointer, touch, or arrow keys, and use the magnifier to check alignment. Magic Color evens out lighting and preserves colored ink. B&W Document uses adaptive thresholding for text. Original keeps the cropped photo’s appearance. Export a reordered batch as a PDF or individual PNG/JPEG files. Exports use up to 4,000 pixels on the long side and 8 megapixels per page. The scanner requires a browser with module workers, WebAssembly, and OffscreenCanvas. Borderless pages may need manual corner placement, and clipped highlights or unreadable shadows cannot be recovered.

The production service worker precaches the scanner and same-origin OpenCV runtime after the first online visit. User photos and scans never enter that cache. The runtime comes from the pinned [official OpenCV.js 4.12.0 build](https://docs.opencv.org/4.12.0/opencv.js). Run `node scripts/scanner-opencv.mjs /path/to/upstream/opencv.js` to reproduce the files in `public/libs/`. The script verifies the upstream SHA-256, separates the original WASM payload, and adapts the JavaScript loader for ES module workers and a CSP with `'wasm-unsafe-eval'` and no general JavaScript eval permission. [OpenCV license](public/libs/opencv-LICENSE.txt).

## Encrypted Vault

The latest shared UI, camera-first scanner, OCR preprocessing and three-minute enforced Vault auto-lock changes are documented in [ARCHITECTURE-UPGRADE.md](ARCHITECTURE-UPGRADE.md), including verification limits and remaining specialized editor migrations.

Open **Encrypted Vault** from the workspace, or use **Save to Encrypted Vault** below a scanner or converter result. Create a master passphrase or PIN. The vault uses Web Crypto AES-256-GCM with fresh 96-bit IVs and non-extractable keys derived with PBKDF2-HMAC-SHA-256 (600,000 iterations and a random 128-bit salt). IndexedDB keeps the salt and password-check ciphertext, opaque record IDs, encrypted lengths, and encrypted file and metadata records. The decrypted search index and preview exist only during the unlocked session. A copied database can be attacked with offline password guesses, so choose a long, unique passphrase.

The vault accepts files without an app-imposed file count or file size cap, including videos. New saves encrypt 2 MiB chunks with separate AES-GCM nonces and authenticate the file ID and chunk position. IndexedDB publishes the searchable record only after every chunk is saved. Existing encrypted records remain readable. The vault shows its encrypted data size separately from the browser’s estimated origin quota and available space. Actual capacity depends on browser storage policy and device space.

After unlocking, DocReady checks whether the browser has granted persistent storage and requests it when needed. The badge appears only after a grant. Persisted storage is protected from ordinary storage-pressure eviction. Explicit browser-data clearing and profile loss can still remove the vault.

Use **Create New Folder** for named, colored folders with custom icons and optional nesting. Change a file’s folder from **Edit** or during its initial save. Deleting a custom folder keeps its files and subfolders, moving them to its parent or Personal. PDF text extraction and image OCR index up to 32,000 characters per file and the first 12 PDF pages. Very large PDFs and images can be saved with text extraction skipped. OCR uses same-origin language assets.

**Backup All as ZIP** offers two archives:

- **Unlocked Structured ZIP** contains ordinary readable files and a manifest with the original folder hierarchy, tags, and extracted search text. Anyone who has the archive can read that information.
- **Encrypted Vault Archive** keeps file content and metadata encrypted using the existing master password. It uses opaque folder and file names in the ZIP and restores the original names from the authenticated manifest. File sizes and the number and nesting of entries remain visible in the ZIP structure.

**Restore Backup** can initialize a vault or merge into an unlocked one. The encrypted format requires the original archive password. An unlocked ZIP restored into a new vault uses a new master password. Restore skips existing record IDs when the same archive is loaded again and retains existing files. Older DocReady `.vault` backups are supported for import. Keep backups outside the browser and keep the master passphrase somewhere safe. There is no password reset.

Ordinary backups use the pinned JSZip build at `/libs/jszip.min.js`, cached with the app. Large backups use the bundled zip.js streaming writer (BSD-3-Clause) and require a browser with a **Save File** picker, such as Chrome or Edge on desktop. The picker is also used for large individual downloads. The preview and ordinary download path is bounded to 48 MiB to avoid keeping large plaintext blobs in memory. ZIP restore reads entries with the bundled streaming reader and authenticates encrypted entries before publishing the restored records. Archive manifests are limited to 32 MiB. These backup and preview constraints do not cap vault intake. ZIP backup and restore work offline once the application’s assets are cached.

## Desktop release and a fresh GitHub checkout

The desktop source and releases are at https://github.com/themaveric-alt/DocReady. Web utility access remains separate from the native-only reader route. Windows, macOS universal and Linux installers are available from the published v1.0.0 release. They are unsigned and need user-side OS testing.

A fresh source checkout prepares pinned local runtime assets before building.

```sh
npm ci
node scripts/prepare-native-assets.mjs
npm run models:prepare
npm run background:prepare
npm run build
```

With Tauri prerequisites installed, generate the application icons and build the platform installer. Use `nsis` on Windows, `dmg` on macOS, or `deb,appimage` on Linux.

```sh
npx @tauri-apps/cli@2 icon public/icons/icon-512.png
npx @tauri-apps/cli@2 build --bundles nsis
```

Version tags such as `v1.0.0` must match the version in the Tauri configuration. The GitHub release workflow builds all three platforms and publishes installers after all jobs pass. See `WEB-DESKTOP-SEPARATION.md` for runtime gates, asset verification, download fallback behavior and remaining reader limitations.
